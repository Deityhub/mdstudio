## 1. Product Overview

**What it is:** A local-first Markdown writing studio and lightweight CMS for blog posts, documentation, and technical articles. The Markdown text is the source of truth: whatever a writer copies or downloads renders identically on GitHub, dev.to, Hashnode, Obsidian, static-site generators (Astro, Hugo, Next.js), and any standard CommonMark renderer.

**Who it is for:** Technical writers, developer bloggers, open-source documentation maintainers, students, and engineers who write on multiple platforms and want zero format lock-in.

**Core Jobs to be Done:**

1. **Write with fidelity:** Live preview that strictly matches production platforms.
2. **Bring content in seamlessly:** Import `.md`, drag-and-drop files, paste raw Markdown, or paste rich text (Google Docs, Notion, web pages) with automatic, clean HTML-to-Markdown conversion.
3. **Take content out anywhere:** Download `.md`, copy raw Markdown, generate self-contained `.md` (images embedded as base64 data URIs), copy rendered HTML, or export standalone `.html`.
4. **Know it's portable:** Real-time portability checker flags non-portable syntax (raw HTML, wiki-links, mermaid, math, local images) tailored to target profiles (Strict CommonMark, GFM extended, GFM without HTML, Wiki notes).
5. **Smart assistance without lock-in:** BYOK (Bring Your Own Key) browser-direct AI for metadata suggestions (title, description, tags) and topic drafting.
6. **Optional cloud sync:** Hosted zero-egress Cloudflare deployment or self-hosted Docker container with SQLite.

### 1.1 Invariants (Rules Never to Break)

1. **Local-first:** Writing, previewing, linting, and exporting work 100% offline without requiring an account or network connection. The backend is strictly additive.
2. **Preview = Export:** Strict CommonMark + GFM. The preview must never apply transforms that the exported text lacks (no auto-`<br>` line breaks, no smart quotes).
3. **Sanitized Output:** Every rendered HTML tree passes through `rehype-sanitize` before DOM insertion to prevent XSS.
4. **Bring-Your-Own-Key AI:** Browser connects directly to AI providers via streaming HTTPS/SSE. Keys live in session memory only, are never sent to our backend, and have no proprietary platform dependencies.
5. **One Codebase, Two Deployments:** Cloudflare Workers + D1 + R2 (official hosted tier) and Docker Node + SQLite + disk volume (self-hosted) share 100% of the Drizzle schema, queries, and business logic. Only storage/driver adapters differ.
6. **Review Before Mutation:** AI generations or cloud sync operations must never silently overwrite or destroy a local draft.
7. **Responsive Parity:** Every workflow (editing, previewing, importing, exporting, linting, front matter editing, AI assistance) must be fully usable on mobile phones, tablets, and desktop displays.

8. **Markdown Is Canonical:** The source and split views edit the same text. Nothing may rewrite the document except through explicit user edits, and nothing emits proprietary syntax.

### 4.2 Checker rules (`src/lib/checker/`)

The Checks panel shows three kinds of issue, all produced by `runChecks(md, profile, config)` and merged by line:

- **Portability rules** (section 4.1), with the writer's on/off and severity choices applied afterwards. The rule ids are listed in `BUILTIN_RULES`; a rule that a profile renders stays quiet on its own.
- **Publication standards**, off until turned on, each with a severity and limits: `title-length` (front matter title, else the first heading), `description-length`, `required-fields`, `heading-structure` (one `#` heading, no skipped levels), `word-count` (as the status bar counts) and `tag-count`. They use `splitFrontMatter`, `getOutline` and `getStats` from `markdown.ts`, so there is still one Markdown parser.
- **The writer's own rules**: plain text (optionally whole-word) or a regular expression, a message in which `{match}` is the text found, and a severity. They run over the text outside fenced code and front matter, report the first match on each line, at most 50 lines per rule, and look at only the first 2,000 characters of a line. A pattern that repeats a repeat (like `(a+)+`) is refused, because a regular expression cannot be interrupted; this is a heuristic guard, noted in `custom.ts`. Up to 50 rules, patterns up to 200 characters.

**Where settings live.** One set per browser, in `localStorage` (`md:check-rules`, validated with zod and replaced by the defaults when invalid), edited in the Rules dialog and exportable and importable as JSON (200 KB limit) so a team can share standards. **A draft can override them** with a `checks:` map in its front matter: `rule: false` or `true` switches a rule off or on, `rule: error|warning|info` sets its severity, and `title-length: { max: 80 }` sets and enables a standard's limits. The ids are those in the Rules dialog. A setting that is not understood becomes an info note (`checks-config`) on the `checks:` line instead of being ignored silently. Overrides never change the browser's settings.

## 5. End-to-End Data Flows

### 5.1 Edit, Render, and Autosave

```text
User keystroke → CodeMirror doc change → Studio.setContent
   ├─ (Deferred render) → unified → markdown AST → hast → rehype-sanitize → rehype-highlight → sanitized HTML string → preview
   ├─ (Memoized analysis) → portability checks, table of contents outline, reading stats
   └─ (Debounce 400ms) → documentStore.save(currentDoc) [IndexedDB]
      Unsaved edits are also flushed on draft switch, leaving the studio, tab hide and pagehide.
      Status line: Saving… / Saved in this browser / Not saved (failures also raise one toast).
Scroll sync: Editor onScroll → compute scroll percentage → Preview scrollToRatio (and vice-versa)
```

### 5.2 Content Ingestion (Import & Paste)

```text
1. File Import (.md, .txt): File API → splitFrontMatter → create new draft or replace current.
2. Rich Paste (text/html): Clipboard event → rehype-parse → rehype-remark → remark-stringify(GFM) → insert Markdown text; toast notification confirms conversion.
3. Image Paste / Drop: in a draft that is not in the cloud (or when hosting is off or fails): File blob → compressImage (canvas max 1600px) → store data URI in draft.images → insert `![alt](./images/filename.png)`.
   In a cloud draft with hosting on: File blob → shrinkImage (PNG/JPEG/WebP/GIF under 300 KB go as they are, anything larger is re-encoded as WebP, or JPEG where WebP can't be written, at up to 1600px and falling quality until it fits 300 KB; 1 MB is the hard limit) → `POST /api/assets` → insert `![alt](https://<host>/a/<id>.<ext>)`. A failure falls back to the local path and says so.
   "Host images (n)" in a cloud draft's menu moves its local images to hosting and rewrites `images/x.png` and `./images/x.png` (Markdown and `<img src>`) to the hosted links; it is the only thing that rewrites existing text, and Ctrl/⌘+Z undoes it.
```

### 5.4 BYOK AI Assistance

```text
1. Set up: the writer saves AI integrations (provider, name, endpoint, models) once, in a separate dialog (`src/lib/ai/integrations.ts`). Signed out, they are remembered in this browser. Signing out or switching account forgets the account's integrations and keys here. The chosen integration and model stay per device. Every AI task then picks an integration and a model from dropdowns. OpenAI, Anthropic and Gemini have a built-in model list, and "Refresh" asks the provider for its current one (`listModels` in `src/lib/ai/models.ts`). 2. Metadata Suggestion: Send draft content → Parse JSON stream → Populate interactive review inputs → "Apply" writes YAML front matter.
3. Topic Drafting: Send topic prompt + notes → Stream Markdown response → "Open as New Draft" (guarantees existing work is never overwritten).
4. Inline actions: with text selected, the AI menu (toolbar, or a button over the selection on wide screens) offers Improve, Fix spelling and grammar, Shorten, Expand, Summarize, Translate and a custom instruction (`src/lib/ai/actions.ts`). Only the selection is sent, as data. The answer is shown as a diff and replaces the selection in one undoable step only on Accept, and only if that text has not changed meanwhile.
5. Fix with AI: in the Checks panel, issues that a rewrite can fix (raw HTML, math, alerts, highlights, wiki-links, GFM extensions, the writer's own rules and standards, missing alt text) have a "Fix with AI" button (`src/lib/ai/fix.ts`). Only the paragraph, code block or front matter the issue is in is sent, with the target profile and the issue message, and the answer goes through the same diff review and Accept as the inline actions. Alt text is written from the file name and the surrounding words; the model never sees the picture.
6. Integration form: "Test connection" lists the provider's models (or, for a custom endpoint with no list, sends one tiny request), and custom endpoints have presets (OpenRouter, Groq, Mistral, Together) that fill the base URL.
7. Guardrails: AbortController cancels active streams; HTTP 401/402/403 errors halt immediately without wasteful retries.
```

### 5.4a Account limits and the admin dashboard

What an account may use is decided in one place, `src/server/limits/catalog.ts`, read with `limitsFor(request, db, userId)`. Each limit resolves from the most specific layer that sets it: the **account's own override** (one JSON object in `users.limits`, read with the row at sign-in), its **plan** (`plans`, by `users.plan`), the **server-wide default** an admin set in the dashboard (`app_settings`), the **environment variable** (kept so self-hosters configure as before), then the **built-in default**. The plans and the server-wide defaults are shared by every account, so they are read once a minute per server instance (a change in the dashboard shows at once on the instance that made it, and on others within a minute), leaving one database read per limit check. Everyone starts on `free`, which changes nothing. Limits: storage and counts (`cloud_docs`, `revisions`, `assets`, `asset_bytes`, `ai_integrations`), sharing and publishing (`share_max_days`, `share_default_days`, `private_links`, `invites_per_day`, `github_publish`) and per-account rate limits (`share_changes_per_hour`, `comments_per_hour`, `github_publishes_per_hour`, `github_reads_per_hour`, `ai_changes_per_hour`). Sign-in and abuse limits are not account limits.

**Admins.** `users.role` is `admin` or `user`. The first account ever created is the admin: the insert sets the role in one statement (`firstAccountIsAdmin`), so two sign-ups cannot both win, and the release migration makes the oldest existing account the admin. Anyone can be made or unmade an admin in the dashboard or with SQL on D1. There is no admin secret: `/api/admin/*` and `/admin` are for a signed-in admin with a confirmed email, and anyone else (signed in or not) gets the same 404 as for a page that does not exist. Writes check the origin and are written to `audit_log`. The dashboard refuses changes that would leave no admin (an admin cannot demote, suspend or delete themselves, and the last admin cannot be removed).

**The dashboard** (`/admin`, noindex, disallowed in robots.txt) has: **Overview** (site totals); **Accounts** (search, and per account: role, plan, suspension, email confirmation, sign out everywhere, delete, usage, its own limits with their sources, and its drafts, share links and images by title and size, which can be removed); **Plans** (make plans that change chosen limits); **Server** (close sign-ups, a site notice shown above the editor, and server-wide default limits); **Audit log**. Admins never see draft text. **Suspending** an account ends its sessions, blocks sign-in (reported only after the right password, so it does not reveal that an address exists) and hides its share links until it is reinstated; its data is kept and its local drafts are untouched. Closing sign-ups refuses new password and GitHub accounts (the very first account is always allowed).

### 5.5 Cloud Drafts and Synchronization

Accounts are optional and the cloud is opt-in. A draft is stored in the cloud only when the writer chooses it, an account may keep a limited number (5 by default, `MAX_CLOUD_DOCS` on the server), and everything else stays in the browser's IndexedDB.

```text
Choosing:    after signing in, a dialog lists this device's drafts (none pre-selected); a draft's menu has
             "Save to cloud" / "Remove from cloud". Removing deletes the cloud copy and keeps the local draft.
Ownership:   a draft in an account's cloud belongs to that account. It is hidden while anyone else, or nobody,
             is signed in (this includes an expired session) and is never offered to another account.
             Drafts not in the cloud are visible to everyone who uses the browser.
Signing out: sync once, then remove the account's cloud drafts (and their local history) from the browser, so
             the next sign-in downloads them again. Drafts with images are listed first (images are not in
             the cloud yet) and can be kept. Without a connection and with unsynced changes the writer must
             choose between staying signed in and keeping those drafts on the device.
Syncing:     only when a draft changed (its hash differs from what the cloud has) and only drafts in the cloud.
             A round pulls first, then pushes; it runs about 3 seconds after a local save, when the tab
             regains focus or comes back online, and every minute, never while signed out. A cloud change to
             a draft with unsaved edits waits for the next round.
Conflicts:   the later edit wins. Each push carries the time of the edit on its device (`editedAt`); when the
             draft moved on since the device last synced, the later edit replaces the server's text, and
             the loser is answered with the server copy. A device whose text is replaced first keeps it as a
             version in the draft's local History ("Replaced by a newer edit elsewhere"). A device clock
             cannot claim more than 5 minutes ahead of the server. An identical text is never a conflict,
             an edit beats a delete, and an edit cannot revive a delete it has not seen.
Limit:       the server refuses a new cloud draft beyond the limit (`limit_reached`) and the draft is local
             again; bringing back a deleted draft needs a free slot too. Deleting frees one.
```

- PULL: `GET /api/sync/pull?since=<cursor>` returns changes and tombstones plus the account's `limit`. The cursor is the server's `updated_at` in milliseconds and is inclusive, so a write in the same millisecond is never missed; applying an already-seen version is a no-op.
- PUSH: `POST /api/sync/push` (up to 50 documents, 5 MB, 1 MB of text each) returns per document `ok`, `conflict` (with the server copy), `limit_reached` or `rejected`. Deleting stores a tombstone and drops the text.
- Scope: title, library name, folder and text. Local images and empty folders stay on the device until hosted images ship.
- Ids: drafts keep their short local ids, sent as `<userId>:<id>` so two accounts can never clash; the server refuses ids outside the caller's prefix, and answers another account's id as "rejected", the same as an unknown one.
- Browser engine (`src/lib/sync/`): per account and per cloud draft, IndexedDB keeps `{ version, hash }` under `sync:<userId>:doc:<id>` plus the pull cursor. The wire contract is `protocol.ts`, shared with `src/server/sync`. The account is remembered in `localStorage` so an offline reload still shows its drafts.
- Cloud history (`src/server/revisions/`): the server keeps the text a push replaces. At most one automatic version per draft per `REVISION_INTERVAL_MINUTES` (5), and text that a later edit from another device takes over is always kept (`reason: replaced`), because nobody else has it. Only the newest `MAX_REVISIONS` (10; `0` switches it off) stay per draft; the oldest are pruned, and an unchanged text is never kept twice in a row. Versions are immutable (never edited or removed one by one) and go when the draft is deleted. The text is stored gzipped as base64 when that is smaller (short or incompressible text stays plain), which shrinks prose to roughly a third, so ten versions of a 10 KB draft take about 45 KB. Local History in the browser keeps its own 50 versions and is cleared at sign-out with the cloud drafts; the cloud's versions are not, and show again in the History panel's "In your cloud" section (compare and restore work as for local versions; a restore is an ordinary edit that syncs).
- GitHub connection (`src/server/github/`): signing in with GitHub asks for no repository access and keeps no token. Publishing needs a separate, explicit **Connect** that asks for `public_repo gist` (or `repo gist` when the writer chooses private repositories) and keeps the access token sealed with AES-GCM (`GH_TOKEN_KEY`, 32 random bytes in base64; the account id is bound in, so a token copied to another account's row does not open, and a changed key just means connecting again). The token never reaches the browser or logs. Only verified accounts can connect; a grant without repository access is refused. The GitHub addresses can be changed with `GITHUB_URL` and `GITHUB_API_URL` (tests, GitHub Enterprise). **Publishing** (`publish.ts`) publishes a cloud draft: the text is the draft's cloud copy (the editor syncs first), and the draft's local images come with the request as data URIs (at most 20, about 4.5 MB of files). Images pasted into the text as data URIs are taken out too (`extractDataImages`), so no base64 is ever committed. Everything goes in one commit through git objects (blobs, a tree on the branch's tree, a commit, a branch update): the file at the chosen path and the images in an `images/` folder beside it, which is where the text already points. **Commit** moves the branch if it has not moved meanwhile (else `conflict`); **pull request** puts the commit on a new branch `mdstudio/<title>-<yyyymmdd>-<hhmm>` and opens a pull request against the chosen branch. A file that is already there is replaced only if this draft put it there and its blob id is unchanged since (kept in `github_publications`), or the writer sets `overwrite`. A **gist** is secret unless `public`, updated in place on later publishes, and made again if it was deleted. Paths, repositories, branches and image names are validated before anything reaches GitHub (`src/lib/github/protocol.ts`), and a token GitHub no longer honours is forgotten so the writer connects again. Only cloud drafts can be published, so the 5-draft limit applies.\n- Share links (`src/server/share/`, contract in `src/lib/share/protocol.ts`): a link is the **published copy** of a cloud draft, made for gathering feedback before the writer publishes elsewhere (mdstudio is an editor to publish _from_, not a blogging platform). Only verified accounts can share, only a live cloud draft can have a link, and there is one link per draft, so links sit inside the 5-draft cloud limit and need no counter of their own. The link keeps its own title and text, which change only when the writer publishes an update; edits to the draft in between are not public. Every link expires: 1 to 7 whole days (`SHARE_MAX_DAYS`), 4 by default (`SHARE_DEFAULT_DAYS`), changeable while live, and a link that has run out answers 404 and is re-published under a new address. Deleting the draft from the cloud removes its link. Publishing and changing expiry are limited to 60 an hour per account. Links are public and indexable, and live ones are listed in `/sitemap.xml` (newest 5,000). The page (`src/routes/s.$slug.tsx`, data from the `loadSharedPage` server function in `src/lib/share/load.ts`) is server-rendered with the title and a description taken from the front matter or the first paragraph (`src/lib/share/page.ts`), a canonical address and no `noindex`; it sends `Cache-Control: public, max-age=0, s-maxage=60`, so a browser always asks again and a revoke or update shows at once. It shows only the published text, the dates and a report link: nothing about the account or the draft's id. The page data comes from `loadPage` (`src/server/share/page.ts`): a public link gives every reader the same data, so it can be cached, and its comments are loaded in the browser; a private link is read for the signed-in reader (the session cookie) with `Cache-Control: private, no-store` and `X-Robots-Tag: noindex`, a signed-out reader gets a sign-in page with no text, and anyone not invited gets a 404. The editor side (`ShareDialog` with who can open it, the comments switch and the invited people, the `ReviewComments` panel, the Library menu item and globe or lock, the header button, `src/lib/share/{api,hooks}.ts`) publishes after saving the draft and syncing it, so the copy is the latest text, and reads the links only when the Share dialog or the Comments panel is opened (no background polling). **Review links** (`src/server/share/{people,comments}.ts`): a link is open to anyone with it (`public`) or only to the owner and to invited addresses (`people`). A reader of a private link must be signed in with a confirmed account on an invited address; a signed-out reader is asked to sign in, and anyone else gets "not found", so nothing about the link is revealed. Private pages are `Cache-Control: private, no-store` with `noindex`, never in the sitemap and never returned by the public read. Whether an account may make private links is an account limit (`private_links`, see "Account limits"), so a plan can gate it. With comments on, signed-in, confirmed readers can comment on the published copy; comments are plain text, shown by display name (never an address), tied to the words the reader selected (the source line of the block and up to 120 characters of the selection) of the copy they were written on, found again by those words after an update, and shown as outdated once an update is published. The writer gets at most one email an hour per link saying that something was said (never what), and an invitation (who shared it, the title, the expiry date and a button) is emailed once per new address. An expired link and its comments are kept 30 days for the owner, and publishing again keeps them under a new address. Not built yet: edit access (waits for M5 collaboration), view counts, custom slugs and embeds (deferred).
- Honest limit: IndexedDB is not encrypted. Removing cloud drafts at sign-out and hiding them afterwards reduces what a shared computer shows; it is not protection against someone who can open the browser's developer tools while a session is active.

### 5.6 Real-time channel

Cloud drafts and share pages are told about changes as they happen, over a WebSocket, instead of asking on a timer. The channel is a foundation: sync uses it first, review comments next, and collaborative editing (Milestone 5) later, on the same sockets.

- **One door, decided once** (`src/server/realtime/routes.ts`): `GET /api/realtime?topic=user|share:<slug>&client=<tab id>` as a WebSocket upgrade (handled in `src/server.ts` before routing). On opening it checks, in this order: the page is from this site (`Origin`), a live session (the HttpOnly cookie; never in the URL), a confirmed email where the server sends mail (like the cloud itself), a valid topic and tab name, 120 sockets an hour per account (`hit`), and for a share the same access rules as reading the link (`viewShare`: public, owner, or an invited confirmed address; anything else is "not found"). After that a socket can only receive: the only thing a client may send is the text `ping`, and anything else closes it (`4003`).
- **Topics.** `user:<id>` (all of an account's tabs and devices; at most 10 sockets) and `share:<id>` (a link's owner and readers; at most 50). One topic is one room; a tab that listens to a share opens a second socket.
- **Events** (`src/lib/realtime/protocol.ts`, zod): `ready` (subscribed), `sync` (pull now), `bye` (the session ended; the socket is closed right after). Each feature adds its own events; an event is never larger than 128 KB, a bigger change sends `sync` instead. A socket only receives what its topic already lets it read over HTTP.
- **Close codes** (private range): `4001` session ended (sign-out, suspension, deletion), `4002` topic full, `4003` bad message, `4004` the socket's session ran out (renew it, then reconnect).
- **Who is told.** `publish(request, topic, event, { exclude })` (`src/server/realtime/publish.ts`) is called after a change is saved; `exclude` is the tab that made it. It never throws and, on Workers, never makes the request wait. A socket whose session has run out is closed instead of sent to.
- **Hosted (Cloudflare).** A Durable Object per topic in its own Worker (`infra/realtime`, `mdstudio-realtime`; previews share `mdstudio-realtime-preview`), which the app binds to as `REALTIME` (`infra/worker-config.ts`, from `REALTIME_SCRIPT` at build). It uses the WebSocket Hibernation API: an idle topic is evicted from memory while its sockets stay open, so it costs nothing, the runtime answers `ping` without waking it, and it wakes for a publish. Workers Free only offers SQLite-backed objects, so the class is created with `new_sqlite_classes`. It has no public address: it is reached only through the binding, and the app puts who is asking in `x-rt-*` headers (without the cookie). The app's own build keeps nitro's WebSocket feature off for Workers, or nitro would take the upgrade first.
- **Self-hosted (Node).** The same door, with nitro's WebSocket support on and an in-process hub (`src/server/realtime/hub.ts`): one container, nothing to configure. A reverse proxy must pass WebSocket upgrades (`Upgrade` and `Connection` headers); Caddy does, nginx needs `proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`.
- **Falls back to polling.** Where the socket is not available (a Workers build without the hub, a proxy that drops upgrades, the free quota used up) clients keep the 60-second poll; real-time only ever removes requests.
- **Cost on the free tier.** A tab costs one Durable Object request to connect, nothing while idle, and a change costs one request to publish. Incoming messages (pings aside) are billed 20 to 1; outgoing are free.

## 6. Authoritative Database Schema (SQLite / Drizzle)

The database schema is defined in `infra/db/schema.ts` and runs identically on Cloudflare D1 and `better-sqlite3`:

```sql
-- Core users table
CREATE TABLE users (
  id TEXT PRIMARY KEY,                       -- UUID v7
  email TEXT NOT NULL UNIQUE,
  email_key TEXT UNIQUE,                     -- The inbox under every spelling: +tag dropped, Gmail dots ignored
  email_verified_at INTEGER,                 -- Set by the emailed link (or by GitHub); NULL until then
  password_hash TEXT,                        -- PBKDF2-SHA256 (WebCrypto, 100k iterations, the Workers cap); NULL for OAuth-only users
  display_name TEXT,
  avatar_url TEXT,
  plan TEXT NOT NULL DEFAULT 'free',          -- which plan's limits apply (see "Account limits")
  limits TEXT NOT NULL DEFAULT '{}',         -- this account's own limits: one JSON object, limit key to number or true/false
  role TEXT NOT NULL DEFAULT 'user',          -- 'admin' can use /admin; the first account ever made is the admin
  suspended_at INTEGER,                       -- set by an admin: cannot sign in or use the cloud; NULL when active
  created_at INTEGER NOT NULL,               -- Unix milliseconds
  updated_at INTEGER NOT NULL
);

-- Active user sessions (cookie-based)
CREATE TABLE sessions (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash TEXT NOT NULL UNIQUE,           -- SHA-256 hash of the session token
  expires_at INTEGER NOT NULL,
  created_at INTEGER NOT NULL
);

-- Linked OAuth identities
CREATE TABLE oauth_accounts (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  provider TEXT NOT NULL,                    -- 'github' | 'google'
  provider_user_id TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  UNIQUE(provider, provider_user_id)
);

-- Synced Markdown documents
CREATE TABLE documents (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title TEXT NOT NULL DEFAULT 'Untitled',
  name TEXT,                                 -- Library label set by renaming
  folder TEXT,                               -- Library folder (one level)
  content TEXT NOT NULL DEFAULT '',
  version INTEGER NOT NULL DEFAULT 1,        -- Monotonically increasing version counter
  content_hash TEXT NOT NULL,                -- SHA-256 of title, name, folder and content
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  edited_at INTEGER NOT NULL DEFAULT 0,      -- When the text was last edited on a device (later edit wins)
  deleted_at INTEGER                         -- Soft delete tombstone for sync propagation
);
CREATE INDEX idx_documents_user_updated ON documents(user_id, updated_at);

-- Immutable version history
CREATE TABLE document_revisions (
  id TEXT PRIMARY KEY,
  document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  version INTEGER NOT NULL,
  title TEXT NOT NULL,
  content TEXT NOT NULL,                     -- The text, or its gzip as base64 when `encoding` says so
  encoding TEXT NOT NULL DEFAULT 'plain',    -- 'plain' or 'gzip-b64' (compressed only when smaller)
  size INTEGER NOT NULL DEFAULT 0,           -- Length of the text itself
  hash TEXT NOT NULL DEFAULT '',             -- So an unchanged text is never kept twice in a row
  reason TEXT NOT NULL DEFAULT 'auto',       -- 'auto' (periodic) or 'replaced' (taken over by a newer edit)
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_revisions_doc_version ON document_revisions(document_id, version DESC);

-- Hosted uploaded image assets
CREATE TABLE assets (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  document_id TEXT REFERENCES documents(id) ON DELETE SET NULL,
  storage_key TEXT NOT NULL UNIQUE,          -- `<random id>.<ext>` in R2 or under DATA_DIR/uploads
  file_name TEXT NOT NULL,
  mime_type TEXT NOT NULL,
  byte_size INTEGER NOT NULL,
  sha256 TEXT NOT NULL,                      -- Deduplication hash
  created_at INTEGER NOT NULL,
  UNIQUE (user_id, sha256)                   -- The same picture is stored once per account
);

-- Public read-only share links: the published copy of one cloud draft
CREATE TABLE share_links (
  id TEXT PRIMARY KEY,
  document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  revision_id TEXT REFERENCES document_revisions(id) ON DELETE SET NULL,  -- unused
  slug TEXT NOT NULL UNIQUE,                 -- 12 random URL-safe characters, never reused
  is_public INTEGER NOT NULL DEFAULT 1,      -- unused until private links exist
  view_count INTEGER NOT NULL DEFAULT 0,     -- unused
  expires_at INTEGER,                        -- always set by the server: every link expires
  created_at INTEGER NOT NULL,
  title TEXT NOT NULL DEFAULT '',            -- the published copy; changes only on "publish update"

  published_at INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX share_links_document_unique ON share_links (document_id);  -- one link per draft
-- share_links also has: access ('public' | 'people'), comments (0 | 1)
CREATE TABLE github_connections (            -- a writer's GitHub connection, for publishing
  user_id TEXT PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  github_user_id TEXT NOT NULL,
  login TEXT NOT NULL,
  scope TEXT NOT NULL,                       -- granted scopes, space separated ("public_repo gist" or "repo gist")
  token_sealed TEXT NOT NULL,                -- AES-GCM, bound to user_id; never returned to the browser

  updated_at INTEGER NOT NULL

  parent_id TEXT,
  version INTEGER NOT NULL,                  -- the published copy it was written on (published_at)
  line INTEGER NOT NULL,                     -- the block's source line, and the start of its text:
  snippet TEXT NOT NULL DEFAULT '',          -- enough to mark it outdated after an update
  body TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  resolved_at INTEGER
);
```

## 8. Security & Privacy Guarantees

**Sign-up protection.** Open sign-up must not be a way to run up the free allowances.

- _One inbox, one account:_ `emailKey` (`src/server/auth/email.ts`) drops a `+tag`, ignores dots in Gmail addresses and maps `googlemail.com` to `gmail.com`; sign-up refuses a key that exists, social sign-in links to it (below), and any spelling signs in to its account.
- _Linking social sign-ins_ (`src/server/auth/social.ts`, shared by GitHub and Google): the provider's own id (`oauth_accounts`, unique per provider) is the identity, never the email. A known identity signs in (a suspended account is refused). Otherwise the provider must report the email as verified (`no_verified_email`). An account with that inbox (`emailKey`) gets the identity added and is signed in, so Google plus GitHub with one email, or a password account plus either, is one account; a suspended account is refused and nothing is linked. When that account's address was never confirmed, its password, sessions and pending links are removed first (whoever pre-registered it may not own the address), and the address counts as confirmed. With no such account a new confirmed, password-less one is made unless sign-ups are closed (`signups_closed`); the user row and its identity are removed together if the second insert fails. Different emails make different accounts. Password sign-up with an existing email answers `email_taken`, whose message points to the social buttons and "Forgot password" without saying which method the account uses.
- _Limits_ (table `rate_limits`, fixed windows, the same SQL on D1 and SQLite): 5 sign-ups per hour per address, 10 failed sign-ins per 15 minutes per email and per address (locked out until the window ends, before any password work, and a success clears the email's count), 3 confirmation emails per hour per account. The address is `cf-connecting-ip`, or `X-Forwarded-For` only when `TRUST_PROXY` is set, since any client can send that header; with neither, only the per-email limits apply.
- _Mail providers:_ `src/server/mail/` sends through a chain of providers (Resend and Mailtrap over HTTP anywhere; SMTP or a folder of JSON files on Node). Each has its free-tier limits (per UTC day and month) in a registry (`providers.ts`; adding one is one entry plus a small sender), counted in `rate_limits` only for sends that succeeded. A send goes to the provider with the most room left, skips any that is full, and falls through to the next on a failure; a provider that fails is left alone for 5 minutes, and a 429 marks it full for the day. `MAIL_PROVIDERS` orders or limits them, `MAIL_<ID>_DAILY`/`_MONTHLY` override the limits. No provider configured means no mail.
- _Email confirmation:_ when the server can send mail, a password account starts unconfirmed and **nothing is sent at sign-up**: the first time the account tries the cloud (a draft's "Save to cloud" or the account menu's "Choose drafts for the cloud…") the app opens a "Confirm your email" dialog that sends the link, and opening it again sends nothing while that link is still good ("Send it again" forces one). People who only write locally never cost a message. Until the link is used the cloud (sync and image hosting) answers 403 `email_unverified`. The one-time link (hash stored, 24 hours, single use, valid only for the address it was sent to) is used. GitHub and Google accounts count as confirmed. A server that sends no mail confirms nothing and blocks nothing. A failed send shows in the dialog, which offers to try again.
- _Email design and retries:_ confirmation and reset mail are sent as plain text plus a designed HTML version (`src/server/mail/template.ts`): the warm paper palette as hex with a dark version for clients that follow the reader's setting, the link also written out under the button, and nothing loaded from the network (no images, fonts or trackers). If sending a confirmation fails, its link is removed again, so the next request tries a second time; once a send succeeds, later requests answer "already sent" until the link is used or expires.
- _Password reset:_ "Forgot your password?" in the sign-in dialog (shown only when the server can send mail) asks for the address and always answers "if an account exists, we sent a link", so it cannot reveal who has one: unknown addresses and inboxes already sent 3 links in the hour are answered identically, the mail is sent after the response goes out (`waitUntil` on Workers), and the same sign-up CAPTCHA applies. The link points to a page (`/reset-password`, noindex), not to a state-changing GET, so mail scanners that open links cannot use it up; the page takes the token out of the address bar. A link lasts an hour, works once, is stored only as a hash, is tied to the address it was sent to and to its purpose (a confirmation link cannot reset a password, nor the reverse), and a new request replaces the older one. A weak password is refused without using the link up. Resetting sets the password (so a GitHub-only account can also gain one), deletes every session of the account and its other pending links, sets the address as confirmed (the person just read mail sent to it) and lifts a sign-in lockout. It does not sign anyone in.
- _CAPTCHA:_ with `TURNSTILE_SECRET` set, sign-up needs a Cloudflare Turnstile token, verified server-side (anything but a clear success fails); the CSP allows Cloudflare's challenge script and frame for it.

1. **HTML Sanitization:** Raw user input is parsed and sanitized using a strict `rehype-sanitize` schema allowing only standard formatting elements, safe attributes, and `data:image/*` or `https://` sources.
2. **Content Security Policy (CSP):** Sent on every HTML response in production by the security-headers middleware (`src/start.ts`, `src/lib/server/csp.ts`). Each request gets a random nonce that TanStack Start stamps on its inline SSR scripts, so `script-src` never needs `'unsafe-inline'`. Styles keep `'unsafe-inline'` because CodeMirror and Radix inject style elements at runtime. `connect-src` allows `https:` and `http://localhost`/`127.0.0.1` because BYOK AI calls go directly from the browser to the writer's provider (including local runners such as Ollama). Fonts are self-hosted, so no third-party origins are needed. The same middleware sets `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` and `Strict-Transport-Security`. It is disabled in `vite dev` (HMR needs inline scripts).
   ```
   default-src 'self';
   script-src 'self' 'nonce-<per-request>';
   style-src 'self' 'unsafe-inline';
   img-src 'self' data: https:;
   font-src 'self';
   connect-src 'self' https: http://localhost:* http://127.0.0.1:*;
   object-src 'none';
   base-uri 'self';
   form-action 'self';
   frame-ancestors 'none';
   ```
3. **Session Management:** Cryptographically random 32-byte session tokens stored as SHA-256 digests in SQLite. Delivered via `HttpOnly`, `Secure`, `SameSite=Lax` cookies. A session lasts 24 hours and slides: use in the second half of its life extends it by another 24 hours, so only someone idle for a full day is signed out. An absolute cap of 5 days from sign-in ends it regardless of activity.
4. **Data Isolation:** All database queries require a verified `user_id` extracted from the server session context. Client-provided user IDs are strictly ignored.
5. **Private AI Usage:** User API keys are held strictly in browser client memory for the active session, never stored in `localStorage`, and never forwarded to our backend.
6. **Self-Host Hardening:** The `ALLOW_SIGNUPS=false` configuration variable allows private instance owners to completely disable registration.

## 9. Deployment Architecture

### 9.1 Hosted Tier (Cloudflare — Zero Cost Baseline)

- **Edge Application & API:** Cloudflare Workers running the TanStack Start runtime.
- **Database:** Cloudflare D1 (Serverless SQLite, 5 GB storage, 5 million reads/day free).
- **Asset Storage:** Cloudflare R2 (10 GB storage, zero egress bandwidth charges).
- **Import and export (bulk):** Export, _Download all drafts (.zip)_, writes each draft as `<Folder>/<title-slug>.md` (unfiled drafts at the top), with the images a draft uses in an `images/` directory beside it and references pointed at `./images/<name>`; duplicate titles get `-2`, `-3`, and a clashing image name is renamed. The text is otherwise unchanged. Version history is not exported. Import accepts several files, a `.zip` (such as this export), or a picked folder: Markdown and `.txt` files become drafts, directories become library folders (nested ones joined as `a / b`), and images referenced by relative path are attached. Hidden files, `__MACOSX` and paths with `..` are ignored; archives over 5,000 files or 256 MB unpacked are refused. A file with no title or heading keeps its file name.
- **PWA and offline:** `public/sw.js` is a hand-written service worker with no build step, registered in production builds only (not in PR previews) as `/sw.js?v=<package version>` so each release is a new worker with its own cache and the old caches are deleted on activate. It fetches `/editor` and `/` with the scripts and styles they link to on install; pages are network first (4 second timeout) and kept for offline, an editor page that was never cached falls back to the cached editor, files under `/assets/` are cache first, fonts, icons and the manifest are stale-while-revalidate, and the page hands the worker the files it has loaded so the first visit is covered too. It never touches other origins (AI providers), `/api/`, `/_` paths, or non-GET requests. What works offline is what has been used online once: the editor, the preview and the checks, plus Mermaid or KaTeX after they were first used. The `Install` button appears when the browser fires `beforeinstallprompt`. Routing rules are unit-tested (`src/lib/pwa/sw.test.ts`) and the offline behavior is covered by e2e specs.
- **Worker size:** the server bundle is about 0.7 MiB gzipped (Cloudflare free plan allows 3 MiB). Mermaid and KaTeX are browser-only and excluded from it through `import.meta.env.SSR`; `scripts/bundle-size.ts` enforces a 1.5 MiB budget and a list of forbidden libraries in CI.
- **Edge Security:** see Sign-up protection (§8).
- **PR previews:** each pull request into `dev` is deployed as its own Worker (`mdstudio-pr-<number>`, workers.dev, `noindex`) by `.github/workflows/preview.yml` and deleted when the PR closes; see `docs/RELEASING.md`.

### 9.2 Self-Hosted Tier (Docker — Single Container)

- **Deployment:** `docker compose -f infra/docker-compose.yml up -d`
- **Architecture:** Alpine Linux container running Node.js + `better-sqlite3`.
- **Persistent Data:** Single mounted Docker volume (`/data`) containing `studio.db` and the `/data/assets` folder.
- **Backups:** Atomic snapshot via `sqlite3 /data/studio.db ".backup /backup/studio.db"`.

## 11. Architectural Decision Records (ADRs)

| ADR        | Decision                                                 | Architectural Rationale                                                                                                                                                                                                                                                                                                      |
| ---------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ADR 01** | Markdown text is the single source of truth              | Prevents proprietary CMS schema lock-in; ensures complete portability across developer platforms.                                                                                                                                                                                                                            |
| **ADR 02** | Unified / Remark / Rehype pipeline                       | Industry-standard Abstract Syntax Tree (AST); enables identical parsing for rendering, linting, and AST transforms.                                                                                                                                                                                                          |
| **ADR 03** | Local-first IndexedDB storage                            | Guarantees instant typing feedback and 100% offline functionality without requiring account registration.                                                                                                                                                                                                                    |
| **ADR 04** | Client-direct BYOK AI integration                        | Eliminates backend proxy server costs, eliminates vendor lock-in, and guarantees maximum user privacy.                                                                                                                                                                                                                       |
| **ADR 05** | Base64 image embedding in self-contained export          | Enables distributing single, self-sufficient Markdown files without hosting dependencies.                                                                                                                                                                                                                                    |
| **ADR 06** | Cloudflare stack for hosted tier                         | Leverages the most generous free-tier edge compute and database, with zero egress fees on R2.                                                                                                                                                                                                                                |
| **ADR 07** | Universal SQLite via Drizzle ORM                         | Unifies Cloudflare D1 and Docker `better-sqlite3` under a single schema, query syntax, and migration pipeline.                                                                                                                                                                                                               |
| **ADR 08** | Single-container Docker deployment                       | Eliminates complex multi-container dependencies (e.g., PostgreSQL + Redis), making self-hosting trivial.                                                                                                                                                                                                                     |
| **ADR 09** | Versioned optimistic concurrency for sync                | Simple, robust, and predictable conflict handling; the later edit wins and the text it replaces is kept in the draft's history, so nothing is destroyed.                                                                                                                                                                     |
| **ADR 10** | Database-backed cookie sessions over JWT                 | Enables immediate session revocation and simplifies Edge/Node authentication compatibility.                                                                                                                                                                                                                                  |
| **ADR 11** | Raw IndexedDB instead of `idb-keyval`                    | The wrapper was a thin layer over ~60 lines; owning it removes a dependency and lets writes resolve on transaction completion.                                                                                                                                                                                               |
| **ADR 13** | Math and Mermaid are profile-gated                       | Preview must match the target platform: render only where it renders, flag everywhere else. Two packages are the one exception to "build, don't install".                                                                                                                                                                    |
| **ADR 14** | Nonce-based CSP instead of `script-src 'unsafe-inline'`  | SSR emits inline scripts; a per-request nonce keeps XSS protection without hashing dynamic payloads.                                                                                                                                                                                                                         |
| **ADR 15** | Push the data over hibernating Durable Object WebSockets | Polling wastes a request per tab per minute and lags by up to that; SSE is one-way (no later collaboration) and keeps a Durable Object awake and billed; hosted pub/sub breaks the $0 and no-vendor rules. Events carry the data (applied by the existing version-gated rules) and a pull only catches up after a reconnect. |

## 12. SEO and Discoverability

- **Single source:** `src/lib/site/seo.ts` holds the site constants, `pageHead()` (title, description, canonical, Open Graph, Twitter), the WebApplication JSON-LD, the sitemap and the IndexNow payload. Every public route builds its head with `pageHead()`; add new public pages to `SITEMAP_ENTRIES` (which feeds `INDEXABLE_PATHS`) so they reach the sitemap and IndexNow.
- **Private pages:** editor routes use `noindex` and no canonical. `/api/` is disallowed in `robots.txt`.
- **Crawlers:** search engines and AI crawlers are explicitly allowed (`public/robots.txt`). `public/llms.txt` summarises the product for AI assistants and must be updated when pages are added.
- **IndexNow:** `public/<key>.txt` proves site ownership; the release workflow runs `scripts/indexnow.ts` after each deploy (non-blocking).
- **Assets:** `public/og.png` (1200x630) and the app icons are generated by `bun run brand` from `public/favicon.svg`; `public/manifest.webmanifest` describes the installable app.
- **Checked by:** `src/lib/site/seo.test.ts` and `e2e/seo.spec.ts`.
- **Guides:** long-form articles live in `content/guides/<slug>.md` (no H1; the page title is the H1) with their metadata (title, description, dates) in `src/lib/site/guides.ts`. The `/guides` index and `/guides/$slug` pages render them with mdstudio's own pipeline (`renderMarkdown`, sanitized), add `TechArticle` and `BreadcrumbList` JSON-LD, an "On this page" table of contents and per-guide sitemap `lastmod`. `src/lib/site/guides.test.ts` enforces the invariants: a file per guide, title at most 60 and description 110 to 160 characters, at least three sections, no checker issues on the GitHub, dev.to and Obsidian profiles, and every guide listed in `public/llms.txt`. To add a guide: write the Markdown, add its metadata, add it to `llms.txt`.
- **Legal pages:** the Privacy Policy (`/privacy`) and Terms of Service (`/terms`) are `content/legal/<slug>.md` (no H1), with their title, description and date in `src/lib/site/legal.ts`, rendered like the guides and linked from the footer and the sitemap. `{{site}}`, `{{contact}}` and `{{repo}}` in the text are filled from `SITE` (`src/lib/site/seo.ts`, which holds the contact address). They describe what the product really does, so a change to what is stored or shared (a new provider, a new kind of data, analytics) must change them in the same pull request, and their date.
